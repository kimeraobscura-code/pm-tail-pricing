# 7패스 적대적 심사

대상 원고: `$1` (비어 있으면 `README.md`. 한국어판을 볼 때는 `README.ko.md`)

## 규율

1. **지어내지 말 것.** 모든 지적은 원고의 특정 줄 또는 `results/` 의 특정 파일·필드를 인용해야 한다. 인용 못 하면 그 지적은 버린다.
2. **문체 지적 금지.** 문체는 Vale 이 결정적으로 잡는다(`bash scripts/check.sh`). 여기서는 내용만 본다.
3. **이미 원장에 적힌 한계는 지적이 아니다.** `verify/claims.json` 의 `caveat`·`status` 를 먼저 읽고, 거기 이미 정직하게 적혀 있는 약점은 중복 지적하지 않는다. 다만 *원고 본문이* 그 한계를 숨기고 있으면 그건 지적이다.

## 절차

### 1단계 — 바탕 읽기 (직접)

```bash
python3 verify/reconcile.py
```

이 출력과 `verify/claims.json`, 대상 원고를 읽는다. 여기서 이미 드러난 `✗`/`△` 는 아래 심사의 입력이지 결론이 아니다.

### 2단계 — 7패스 병렬 심사

Task 를 **7개 동시에** 띄운다. 각 패스는 독립이고, 서로의 결과를 보지 않는다. 각 패스는 지적을 JSON 배열로 돌려준다:

```json
[{"pass":"P3","severity":"major","claim_id":"C5-decay-ratio",
  "where":"README.md:104","finding":"...","why_it_matters":"...",
  "evidence":"results/prereg2_result.json KXGOLDW.fit.c=1.796",
  "fix":"..."}]
```

`severity` 는 `fatal`(제출 불가) / `major`(심사자가 먼저 집는다) / `minor`(고치면 좋다) 셋 중 하나.

**P1 주장-증거 대조.** 원고의 모든 수치를 세고, 각각이 `results/` 의 어느 파일 어느 필드에서 나오는지 되짚는다. 되짚기 실패한 수치를 전부 나열한다. 원고에만 있고 원장(`claims.json`)에 없는 수치도 지적 대상이다.

**P2 식별과 교란.** 각 결론에 대해 "같은 데이터를 만드는 다른 설명"을 최소 2개 만들고, 원고가 그걸 배제하는지 본다. 이 논문의 핵심 주장(§3 편의는 가격이 아니라 유동성 현상)이 표적이다.

**P3 강건성.** 명세를 바꾸면 결론이 뒤집히는 지점을 찾는다. `STALE_MAX` 를 120분에서 5분으로 바꿨을 때 §3 이 무너진 전례가 있다. 다른 임의 상수(구간 경계 0.15, 지평 12시간, tol)에도 같은 취약성이 있는지 본다.

**P4 표본과 선택편의.** n, 기간, 포함·제외 규칙을 전부 뽑는다. 양방향 호가가 있는 행사가만 비교하는 식의 선별, n=2 이벤트에서 끌어낸 일반화, 생존편의를 찾는다.

**P5 선행연구 배치.** 예측시장 선호-비선호 편의·호가단위 문헌에서 이 논문이 무엇을 새로 말하는지, 이미 알려진 것을 새 발견처럼 쓰고 있지 않은지 본다. 인용이 필요한데 없는 자리를 짚는다.

**P6 재현성.** `claims.json` 의 모든 `recompute` 경로, `README` 의 재현 절차, 필요한 키·계정을 실제로 확인한다. 레포만 받은 제3자가 어디서 막히는지 구체적으로 적는다.

**P7 등급 정합성.** 각 주장의 `status`(confirmed/provisional/open)가 증거 강도에 맞는지, 원고 본문의 어조가 그 등급과 맞는지 본다. provisional 인데 본문이 단정하면 지적이다.

### 3단계 — 반증 검증

2단계에서 나온 지적을 모아, `severity` 가 `fatal`/`major` 인 것마다 Task 를 **하나씩 띄워** 반대편을 맡긴다. 그 Task 의 임무는 지적을 **기각하는 것**이다: 원고나 데이터에 이미 답이 있는지, 인용된 증거가 실제로 그 말을 하는지 확인한다.

- 기각되면 버린다.
- 살아남으면 `verdict: "confirmed"` 를 붙인다.

이 단계를 건너뛰지 말 것. 검증 없는 심사는 그럴듯한 헛지적을 만들고, 그걸 고치느라 멀쩡한 원고가 망가진다.

### 4단계 — 보고

`review/` 에 `seven-pass-<YYYY-MM-DD-HHMM>.md` 로 쓴다. 형식:

```markdown
# 7패스 심사 — <날짜>
대상: <원고> (<커밋 해시>)
살아남은 지적: fatal N · major N · minor N  (제기 N건 중)

## fatal
### [F1] <한 줄 요약>
- 위치: README.md:104
- 지적: ...
- 근거: ...
- 반증 시도 결과: ...
- 수정안: ...
```

마지막에 **다음 한 수 3개**를 우선순위대로 적는다. 원고를 고치지는 않는다. 심사와 수정은 분리한다.
